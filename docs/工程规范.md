# 工程规范

- 状态：第五版，已于 2026-08-21 获用户批准
- 实施状态：阶段 1 命中 `blocked-official-api`；禁止继续实现 workaround
- 上级入口：`docs/开发计划.md`
- 唯一职责：目录、官方 API 证据、禁止实现、退休边界、依赖方向、规模和质量门禁

## 1. 工程原则

1. 官方优先：使用 DSH、Cordis、RTK、GitHub 和 Node 的公开 API。
2. 简单优先：一个业务 Cordis Service；没有两个真实调用方时不提取通用 abstraction。
3. 稳定优先：缺少官方 seam 时停止，不以兼容层、反射或源码技巧继续。
4. 单一真相：活动 pointer、已安装 segments、Release 目录、跨版本 gain 和 UI snapshot 各有一个 Owner。
5. 生命周期明确：event、shellEnv、timer、Remote、Slot、subprocess 和临时目录都可释放。
6. 可验证：测试真实 contract 和失败边界，不用大量 mock 构造不存在的架构。

## 2. 官方 API 证据门禁

任何 DSH/RTK 接线在编码前都要记录：

| 字段     | 要求                                           |
| -------- | ---------------------------------------------- |
| 能力     | 要使用的 service、event、CLI 或 package export |
| 目标版本 | DSH rc.7/rc.1 或候选 RTK 版本                  |
| 公开证据 | 官方文档 URL 和目标 package `.d.ts`/CLI help   |
| 生命周期 | 注册、取消、超时和 disposer                    |
| 安全位置 | 相对 approval、sandbox、日志和用户输入的位置   |
| 失败行为 | 不可用、超时、未知输出和升级漂移时的结果       |

只有“官方文档 + 目标版本公开 surface”同时成立才可编码。仅在 `master/develop` 源码中出现、但目标版本未导出的能力不能使用。

阶段 1 必须先在 DSH `0.1.0-rc.7` 和 `0.1.1-rc.1` 证明 Host/Client/Typert/loader/Slot 最小闭环。任一版本失败都暂停项目，不以抬高最低版本、Host-only 发布或 workaround 规避。

## 3. 禁止实现

1. 禁止修改、patch、vendor 或 fork DSH/RTK 源码。
2. 禁止把 DSH checkout、内部源码或协议声明复制进本项目构建流程。
3. 禁止反射 service、递归枚举 live object、访问私有字段或依赖原型形状。
4. 禁止 monkeypatch `fs`、module loader、Cordis registry、generator 或 Node global。
5. 禁止导入 package exports 未公开的深层路径。
6. 禁止手写或文本拼接 Typert artifact、Remote contribution 和 codec。
7. 禁止假 DSH workspace、symlink/junction projection 或修改 manifest 诱导 generator。
8. 禁止替换 Bash/Pwsh executor、重复注册 `ctx.shell` 或在 executor 内改写 command。
9. 禁止修改工具参数、approval identity 或 sandbox policy。
10. 禁止复制 RTK rewrite 白名单、解析 RTK SQLite 或实现第二套 Token 算法。
11. 禁止为 RTK `v0.44.2` 之前版本添加专用兼容分支。
12. 禁止“为了以后可能需要”创建空目录、空 service、万能 port 或 fallback。

命中任一项时结果必须是 `blocked-official-api`、修正 Owner 或暂停，不能提交 workaround。

## 6. 依赖方向

```text
shared schema
  -> host pure helper
  -> RtkService
  -> guidance / shellEnv / Remote projection
  -> Client controller
  -> overlay / dashboard / release picker
```

约束：

1. Host 不导入 Client。
2. Client 只导入 shared contract 和官方 generated Remote，不导入 Host 实现。
3. releases 不调用 UI，gain 不调用下载。
4. wrapper 不读取 GitHub、不切换 active pointer、不解析 gain。
5. guidance 只读取 RtkService 活动 snapshot。
6. Remote 只校验输入并调用 RtkService。
7. React component 通过一个 typed controller/hook 调用 Remote。
8. 禁止循环依赖、双向 service reference、全局 mutable singleton 和模块加载时后台任务。

## 7. 抽象与复杂度

### 7.1 最小抽象

1. 一个调用点使用直接函数，不创建 interface + implementation + factory 三层。
2. 两个 Owner 只有语义完全一致时才共享 helper。
3. 测试替换网络、文件或 subprocess 时，只在 RtkService 构造边界传一个小 dependency object。
4. 不为每个 Node API 创建单独 port。
5. 状态机只服务候选下载、校验、测试、激活这一条可恢复事务。
6. UI 轮询 snapshot，不在首版引入 observable/event bus。

### 7.2 规模门禁

所有手工维护 TypeScript、TSX、JavaScript、CSS、JSON、YAML、Markdown、脚本和测试最多 400 个物理行，目标不超过 250 行。

| 指标           | 硬限制 |
| -------------- | ------ |
| 单函数物理行   | 60     |
| 圈复杂度       | 10     |
| 最大嵌套深度   | 4      |
| 参数数量       | 5      |
| 单文件公开导出 | 8      |

例外只包括 `pnpm-lock.yaml`、`lib/`/`dist/` 官方工具生成物、coverage、Playwright 和 package manager 派生目录。手工 fixture、配置、文档和测试不是 generated exception。

## 8. TypeScript 与契约

1. 开启 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`useUnknownInCatchVariables`、`noImplicitOverride` 和 `noFallthroughCasesInSwitch`。
2. 禁止 `any`；外部 JSON 从 `unknown` 经 Zod 或官方 generated codec 收窄。
3. Host/Client 只传 lossless JSON。
4. Error 投影为稳定 code、message 和最小 metadata；不传 Error、stack 或绝对路径。
5. 时间使用 epoch milliseconds 或 ISO-8601；Release 身份使用 release id、asset id 和原始 tag。
6. support tier 由候选 binary reported version 计算，不按 tag 字符串猜测。
7. package public API 只暴露插件入口、必要 shared type 和官方要求的 Client/Typert entry。

## 9. 中文注释

维护型源码保留三层中文注释：

1. 文件级：Owner、输入输出、生命周期和禁止职责。
2. 函数级：参数、返回、失败语义和不变式。
3. 关键语句级：checksum、安全解压、支持等级、活动切换、跨段聚合、wrapper 环境、缓存和 cleanup ownership。

注释解释“为什么”和“失败会怎样”，不逐行翻译语法。官方 generated 文件只保留生成器头，不手改。

## 10. 测试策略

| 层级         | 覆盖内容                                                |
| ------------ | ------------------------------------------------------- |
| pure unit    | 资产匹配、checksum、路径安全、support tier、gain 聚合   |
| service unit | Release cache、活动切换、segments、错误投影             |
| integration  | 真实 `v0.45.0`、fixture repo、跨段 global/project gain  |
| DSH contract | rc.7/rc.1 Remote、loader、Slot、shellEnv、卸载 disposer |
| Client       | 三标签、Release 选择器、轮询和 partial/stale 状态       |
| package      | `pnpm pack --dry-run`、exports、files、安装/卸载        |

覆盖率最低值：statements/lines/functions 85%，branches 80%。releases、checksum、archive、activation、gain aggregation 和 wrapper 单独要求 statements/lines/functions 95%、branches 90%。
