# 数据与界面

- 状态：第五版，已于 2026-08-21 获用户批准
- 实施状态：等待阶段 1 官方双端闭环通过后实施
- 上级入口：`docs/开发计划.md`
- 唯一职责：跨版本 Token 口径、三标签页、Release 选择器和最小 Remote

## 1. 数据范围

Host 对每个实际安装的 Release segment 使用该段自己的 wrapper：

```text
<segment-wrapper> gain --all --format json
<segment-wrapper> gain --project --all --format json
```

project 调用以 Host 验证后的仓库根为 cwd。每个 wrapper 固定对应 binary、版本化 `RTK_DB_PATH` 和遥测禁用环境。

明确边界：

1. 不直接读取、查询或合并 SQLite。
2. 不用当前 binary 读取其他 Release 的 data segment。
3. 只有实际安装且 gain schema 可读的 segment 进入求和。
4. GitHub 上仅可浏览、但从未安装的 Release 不产生统计数据。
5. 单段失败不丢弃其他段；结果标记 `partial` 并列出不可读段。
6. Token 是 RTK 基于输出的估算，不等于模型供应商账单 Token。

聚合结果必须包含：

```ts
interface RtkAggregateSource {
  releaseId: number
  tagName: string
  supportTier: 'guaranteed' | 'best-effort'
  readable: boolean
  stale: boolean
  reasonCode?: string
}
```

以及 `sourceReleases`、`unreadableReleases`、`partial`、`updatedAt` 和 `stale`。缓存必须绑定 release id、data revision 和 scope，不能把一个 Release 的缓存冒充另一段。

## 2. 跨版本指标

| UI 指标  | 聚合公式                                    |
| -------- | ------------------------------------------- |
| 已节省   | `sum(summary.total_saved)`                  |
| 总接管   | `sum(summary.total_input)`                  |
| 已返回   | `sum(summary.total_output)`                 |
| 节省率   | `sum(saved) / sum(input)`                   |
| 接管命令 | `sum(summary.total_commands)`               |
| 总耗时   | `sum(summary.total_time_ms)`                |
| 平均耗时 | `sum(time) / sum(commands)`                 |
| 趋势     | daily/weekly/monthly 按周期键合并后重算比例 |

分母为 0 时比例返回 `null`，Client 显示短横线。日期边界由各 RTK gain JSON 的周期键决定，Client 不按浏览器时区重新分桶。

悬浮球固定显示：

```text
已节省 / 总接管
{totalSaved} / {totalInput}
```

悬浮球标注“跨已安装版本 · 估算 Token”。面板顶部单独显示当前活动 tag，避免把活动版本与统计覆盖范围混淆。

## 3. 三标签页

### 3.1 总览

显示：

1. 当前活动 Release tag、支持等级、stable/prerelease、发布时间和安装时间。
2. 跨所有可读 segment 的总接管、已返回、已节省、节省率、命令数和平均耗时。
3. daily/weekly/monthly 聚合趋势。
4. 最近 7 天与此前 7 天的接管、返回、节省和命令数差值。
5. 参与聚合的 Release、不可读 Release 和 partial/stale 状态。
6. Release 目录摘要、上次检查时间和“选择版本”。
7. 当前候选事务的下载、校验、测试、激活或回滚状态。
8. 最近一次候选测试的项目、耗时和脱敏失败原因。

### 3.2 今日

显示：

1. 今日跨可读 segment 的总接管、已返回、已节省、节省率、命令数和平均耗时。
2. 今日接管与返回对比。
3. 今日与昨日绝对差值和百分比；昨日为 0 时只显示绝对差值。
4. 今日参与聚合和不可读的 Release 数量。
5. 今日无数据时显示零值空状态，并保留昨日基线。

### 3.3 当前仓库

范围解析：

```text
current session id -> byId[current].cwd -> Host 最近 .git 根 -> cwd fallback
```

显示：

1. 仓库名称和安全显示路径。
2. 该仓库跨可读 segment 的总接管、已返回、已节省、节省率、命令数和耗时。
3. 仓库各指标占跨版本全局对应指标的比例。
4. 仓库今日与昨日对比。
5. 仓库 daily/weekly/monthly 聚合趋势。
6. 仓库范围内的 source/unreadable Release 状态。

没有当前 Session 或 cwd 时显示明确空状态，不回退到全局。前台 Session 切换时取消旧请求。

## 4. 暂缓“未命中语句”

首版不实现第四个“未命中语句”标签页：

1. 首版不透明拦截或改写 DSH shell 命令。
2. RTK `discover` 没有承诺适用于 DSH 的稳定 JSON contract。
3. 自行监听 shell、调用 `rewrite` 分类并保存命令会新增第二套诊断真相和敏感数据面。

只有 RTK 提供适用于 DSH 的官方机器接口，或 DSH 提供文档化且不可变审计的观测 seam，并经用户再次批准，才恢复该标签页。

## 5. Release 选择器

目录覆盖 GitHub 官方仓库所有 `draft:false` Release。

### 5.1 控件

1. 搜索：匹配 tag 和 Release name。
2. 筛选：`全部`、`保证兼容`、`尽力兼容`、`稳定版`、`预发布`、`已安装`，默认 `全部`。
3. 刷新：图标按钮和 tooltip。
4. 当前活动版本：固定状态行，不混入分页排序。

筛选只帮助浏览，不能隐藏不受保证的旧版，也不能把 stable 变成隐式安装通道。

### 5.2 Release 行

每行显示：

1. tag、name、发布时间和 stable/prerelease。
2. `保证兼容` 或 `尽力兼容`；无法预判时显示“下载后检测”。
3. 当前平台官方资产和 digest/checksum 状态。
4. `当前`、`已安装`、`历史版本`、`当前平台不可用` 等状态。
5. 最近一次候选测试结果。
6. 查看详情，以及条件满足时的“安装并切换”“切换”或“重新测试”。

所有公开 Release 行都可选中并查看详情。缺本平台资产或可信校验值时禁用下载/激活并显示原因；`v0.44.2` 之前版本不会因此从目录隐藏。Host 使用 cursor 分页，每页 30 条，catalog revision 变化时重置 cursor。

### 5.3 确认与失败

1. prerelease、历史版本和 best-effort 候选需要简短二次确认。
2. best-effort 文案明确“插件不保证此版本可用，仍将执行完整测试”。
3. 不提供跳过 checksum 或兼容性测试的选项。
4. 下载、测试或激活失败时继续使用旧活动 Release。
5. 失败报告只包含稳定 code、测试项、耗时和脱敏 message。
6. 切换成功后保留旧 segment 数据并使跨版本聚合缓存失效重算。

## 6. Remote 契约

阶段 1 已通过的官方 Client/Typert 链路用于以下接口：

```ts
rtkDashboard.snapshot(request: {
  scope: 'overview' | 'today' | 'repository'
  sessionId?: string
}): Promise<RtkDashboardSnapshot>

rtkDashboard.releases(request: {
  cursor?: string
  limit: number
  filter: 'all' | 'guaranteed' | 'best-effort' | 'stable' | 'prerelease' | 'installed'
  query?: string
  forceRefresh: boolean
}): Promise<RtkReleasePage>

rtkDashboard.applyRelease(request: {
  releaseId: number
  assetId: number
  catalogRevision: string
}): Promise<RtkUpdateReceipt>
```

简化规则：

1. 不建立 observable；Client 在展开时 5 秒、折叠时 15 秒轮询 snapshot。
2. update receipt 返回 transaction id；进度随 snapshot 读取。
3. Remote 只校验参数并投影 RtkService，不包含业务逻辑。
4. Host 不发送 GitHub 原始 JSON、下载 URL、绝对路径、Error 或 stack。
5. 不维护手写 codec 或按 DSH 内部结构分支的 fallback。

## 7. 悬浮球与面板

### 7.1 悬浮球

1. 注册到官方 `shell.overlay`，id 为 `rtk-token-overlay`。
2. 默认右下角；桌面边距 24px，移动端 12px。
3. 固定 88px 圆形尺寸，加载和错误状态不改变几何。
4. 使用 `Intl.NumberFormat` 紧凑格式；tooltip 提供完整值和聚合范围。
5. 自身 `pointer-events:auto`，overlay 其他区域保持 click-through。
6. 支持 `aria-label`、`aria-expanded`、focus ring 和 Enter/Space。

### 7.2 拖动

1. 使用 Pointer Events 和 pointer capture。
2. 移动超过 6px 才判定拖动。
3. 位置限制在视口内。
4. 拖动期间关闭 transition，释放后恢复。
5. 首版不持久化位置。

### 7.3 详细面板

1. 桌面最大宽度 420px，移动端不超过视口减 24px，最大高度 70vh。
2. 顶部显示活动 tag、运行状态、Release 入口、刷新和关闭。
3. tab 固定为“总览、今日、当前仓库”。
4. 内容区独立滚动；窄屏保持文本和图标不重叠。
5. `Escape` 关闭，不强制焦点陷阱。
6. 使用 Lucide 和 DSH theme token；不用渐变、装饰球、嵌套卡片或全局主题覆盖。
7. 覆盖 loading、ready、empty、partial、stale、failed、downloading、verifying、testing、activating 和 rolled-back。

## 8. 浏览器验收

1. `1440x960`、`768x1024`、`390x844` 三档视口。
2. 悬浮球不遮住发送控件，拖动阈值和点击正确。
3. 三个 tab 与 Release popover/sheet 不溢出视口。
4. 350 条合成目录验证分页、全部支持等级和筛选。
5. 最长 tag、资产名、失败原因和大数字不重叠。
6. guaranteed/best-effort、stable/prerelease、可用/不可用清晰区分。
7. 候选测试失败不会显示为当前版本。
8. Session 切换不会闪回旧仓库数据。
9. 浅色、深色、键盘焦点和 reduced motion 可读。
10. 其他 Slot entry 仍可交互。
