# 数据与界面

- 状态：第四版计划组成部分，已批准，实施中
- 上级入口：`docs/开发计划.md`
- 唯一职责：Token 数据口径、四标签页、Release 选择器、Remote 和浏览器交互

## 1. 数据来源

Host 对每个已确认 Release 数据段使用其对应保留二进制执行：

```text
<segment-rtk> gain --all --format json
<segment-rtk> gain --project --all --format json
```

project 调用以 Host 解析后的仓库根为 cwd。每次调用携带该段专属 `RTK_DB_PATH`，设置 5 秒超时，先经过与候选测试相同的 strict schema，再进入聚合器。Client 不解析 RTK 原始输出，不读取 SQLite。

聚合输出必须包含：

- `sourceReleases`：参与结果的 release id/tag。
- `partial`：是否有历史段不可读。
- `unreadableReleases`：失败段及结构化原因。
- `updatedAt`：本次成功计算时间。
- `stale`：是否返回最后成功缓存。

## 2. 跨版本聚合公式

| UI 指标  | 公式                                        |
| -------- | ------------------------------------------- |
| 已节省   | `sum(summary.total_saved)`                  |
| 总接管   | `sum(summary.total_input)`                  |
| 已返回   | `sum(summary.total_output)`                 |
| 节省率   | `sum(saved) / sum(input)`                   |
| 接管命令 | `sum(summary.total_commands)`               |
| 总耗时   | `sum(summary.total_time_ms)`                |
| 平均耗时 | `sum(time) / sum(commands)`                 |
| 趋势     | daily/weekly/monthly 按周期键合并后重算比例 |

分母为 0 时比例返回 `null`，Client 显示短横线，不伪造 0% 或无限值。RTK daily 日期是日期边界唯一权威，Client 不按浏览器时区重新分桶。

悬浮球固定显示：

```text
已节省 / 总接管
{totalSaved} / {totalInput}
```

所有绝对值标注“估算 Token”。

## 3. 四标签页

### 3.1 总览

范围：插件数据目录首次安装成功至当前时刻，跨所有可读 Release 数据段。

显示：

1. 当前活动 Release tag、stable/prerelease 类型、发布时间和安装时间。
2. Release 目录摘要、上次检查时间、“检查 Release”和“选择版本”操作。
3. 活动更新事务的下载、校验、测试、激活或回滚进度。
4. 最近一次候选测试报告，包括每项状态、耗时和脱敏失败原因。
5. 安装以来总接管、已返回、已节省、节省率、命令数和平均耗时。
6. 接管与返回并列对比，已节省作为差值。
7. daily/weekly/monthly 趋势和参与汇总的 Release 列表。
8. 最近 7 天与此前 7 天的接管、返回、节省、命令数和节省率差值。
9. rewrite hit/miss/technical 和命中率。
10. partial 时显示受影响 Release，不隐藏统计缺口。

### 3.2 今日

1. 今日总接管、已返回、已节省、节省率、命令数和平均耗时。
2. 今日接管与返回条形对比。
3. 今日与昨日的绝对差值和百分比；昨日为 0 时只显示绝对差值。
4. 今日 rewrite hit/miss/technical 和命中率。
5. 今日无数据时显示零值空状态，并保留昨日基线。

### 3.3 当前仓库

范围解析：

```text
current session id -> byId[current].cwd -> Host 最近 .git 根 -> cwd fallback
```

显示：

1. 仓库名称和规范化根目录的安全显示值。
2. 仓库安装以来跨 Release 总接管、已返回、已节省、节省率、命令数和耗时。
3. 仓库各指标占全局对应指标的比例。
4. 仓库今日与昨日对比。
5. 仓库 daily/weekly/monthly 趋势。
6. 仓库 rewrite hit/miss/technical 和命中率。

没有当前会话或 cwd 时显示明确空状态，不回退到全局。前台会话切换时取消旧请求。同一仓库多个 Session 聚合在一起，不使用“当前会话 Token”文案。

### 3.4 未命中语句

1. 显示未命中总次数、不同语句数、最近时间和整体 rewrite 命中率。
2. 提供“全部、今日、当前仓库”分段筛选。
3. 默认按 `lastSeenAt` 倒序。
4. 每项显示脱敏语句、原因、Release tag、次数、首次/最近时间、shell 和仓库。
5. 使用 cursor 分页或虚拟列表，不一次渲染 1000 项。
6. technical fallback 只显示为运行状态，不进入未命中列表。
7. 空状态使用“当前范围内没有 RTK 未命中语句”。

## 4. Release 选择器

### 4.1 入口与布局

“总览”中的版本区域使用一行紧凑状态和一个“选择版本”按钮。点击后打开非模态 popover；移动端使用同内容的底部 sheet。不得把版本列表嵌套成多层卡片。

顶部控件：

- 搜索框：匹配 tag 和 Release 名称。
- 筛选分段：`全部`、`稳定版`、`预发布`、`已安装`；内部枚举仍为 `all/stable/prerelease/installed`。
- 刷新图标按钮：强制重新检查目录，带 tooltip。
- 当前活动版本固定在列表顶部的独立状态行。

筛选只帮助浏览，默认“全部”，不能把 stable 变成隐式门禁。

### 4.2 Release 行

每行显示：

1. tag 和 Release 名称。
2. `稳定版` 或 `预发布` 标签。
3. 发布时间。
4. `当前`、`已安装`、`历史版本`、`不可用于当前平台` 等状态。
5. 当前平台资产名和校验来源：`checksums.txt` 或 GitHub asset digest。
6. 最近一次该 Release 测试结果（如存在）。
7. 整行始终可选中并打开详情，即使当前平台不可安装。
8. 可用操作：“安装并切换”“切换”“重新测试”或禁用状态原因。

列表按 Host cursor 每页 30 条加载，滚动到底显示“加载更多”。catalog revision 变化时重置 cursor，避免重复或漏项。

### 4.3 显式风险确认

选择 prerelease 时确认框说明“这是预发布版本，仍会执行完整兼容性测试”。选择发布时间早于活动版本的 Release 时说明“这是历史版本切换，不会删除当前版本数据”。

确认框不得使用恐吓文案，不提供跳过测试选项。stable 且不早于当前版本可直接进入候选事务。

### 4.4 不可用与失败

所有公开 Release 都出现在目录且可选中查看详情。以下情况只禁用候选事务和激活操作，并显示精确原因；不能禁用详情选择或隐藏该行：

- 当前平台没有官方资产。
- checksum 与 asset digest 都不可用。
- 两种校验值不一致。
- 资产名冲突或归档不安全。
- 版本探测与 tag 不匹配。
- 强制兼容性测试失败。

前四项在目录/校验阶段可提前展示；后三项在候选事务后显示。用户可重试下载或重跑测试，但不能强制激活。

## 5. Strict Remote 契约

```ts
rtkDashboard.summary(request: {
  scope: 'overview' | 'today' | 'repository'
  sessionId?: string
  cwd?: string
}): Promise<RtkDashboardSummary>

rtkDashboard.misses(request: {
  scope: 'all' | 'today' | 'repository'
  sessionId?: string
  cwd?: string
  cursor?: string
  limit: number
}): Promise<RtkMissPage>

rtkDashboard.releases(request: {
  cursor?: string
  limit: number
  filter: 'all' | 'stable' | 'prerelease' | 'installed'
  query?: string
  forceRefresh: boolean
}): Promise<RtkReleasePage>

rtkDashboard.applyRelease(request: {
  releaseId: number
  tagName: string
  assetId: number
  catalogRevision: string
}): Promise<RtkUpdateAccepted>

rtkDashboard.retestActive(): Promise<RtkUpdateAccepted>
```

`applyRelease` 立即返回 transaction id，不等待下载和测试。Host observable 推送 `RtkUpdateSnapshot`。同一候选已有事务时返回现有事务；另一候选正在运行时返回结构化 `update-busy`。

`RtkReleasePage` 只投影最小字段：id、tag、name、publishedAt、prerelease、platform status、asset identity、installed/active、last test。不得向 Client 发送 GitHub 原始 JSON、下载 URL、绝对路径或 Error 实例。

Host 对每个 Release segment 的 gain 使用 5 秒缓存并去重并发请求；目录页使用 ETag 与 catalog revision；统计失败保留最后成功值并标记 stale/partial。

## 6. 悬浮球与面板

### 6.1 悬浮球

1. 注册到 `shell.overlay`，id 为 `rtk-token-overlay`。
2. 默认右下角，桌面边距 24px，移动端 12px。
3. 固定 88px 圆形尺寸，加载和错误状态不改变几何。
4. 使用 `Intl.NumberFormat` 紧凑格式；tooltip 和面板提供完整值。
5. 自身 `pointer-events: auto`，overlay 其他区域保持 click-through。
6. 提供 `aria-label`、`aria-expanded`、focus ring 和 Enter/Space。

### 6.2 拖动

1. 使用 Pointer Events 和 pointer capture。
2. 移动超过 6px 才判定拖动。
3. 位置约束在视口内。
4. 拖动期间关闭 transition，释放后恢复。
5. 页面刷新后恢复默认位置，不增加持久化 Owner。

### 6.3 详细面板

1. 桌面最大宽度 420px，移动端 `min(420px, calc(100vw - 24px))`，最大高度 70vh。
2. 顶部显示运行状态、活动 tag、可用 Release 数、刷新和关闭图标。
3. 四个 tab 固定为“总览、今日、当前仓库、未命中语句”。
4. 窄屏采用稳定四列，图标在文字上方；内容区独立滚动。
5. 展开时刷新当前 tab；折叠摘要 15 秒、展开 5 秒；更新进度使用 observable。
6. `Escape` 关闭，不强制困住非模态焦点。
7. 使用 Lucide、DSH 主题变量、清晰边框和有限阴影；不用渐变、装饰球、嵌套卡片或全局主题覆盖。
8. 覆盖 loading、catalog-loading、catalog-failed、candidate-selected、downloading、verifying、testing、activating、rolled-back、unsupported、partial、stale、empty 和 ready。

## 7. 浏览器验收

Playwright 在 `1440x960`、`768x1024`、`390x844` 验证：

1. 悬浮球不遮住发送控件，拖动和点击阈值正确。
2. 面板、四 tab 和 Release popover/sheet 不溢出视口。
3. 使用至少 350 条的合成目录验证分页不会导致长任务或一次性 DOM 膨胀；目录完整性另由 Host 与 GitHub API 的 Release id 集合对账证明。
4. stable/prerelease/历史/不可用状态可区分，但 stable 不成为默认过滤门禁。
5. 最长 tag、资产名、失败原因和大数字不重叠。
6. 测试失败的候选不会显示为当前版本。
7. 前台 Session 切换不闪回旧仓库数据。
8. 浅色、深色、键盘焦点和 reduced motion 可读。
9. 其他 Slot entry 仍可交互。
