## 1. 修订原因

第四版要求透明接管 DSH Bash/Pwsh、在 executor 内调用 `rtk rewrite`，并要求独立包生成 Typert Remote。核对 DSH 官方契约和现有实验代码后确认：

1. DSH `tools/pre-execute` 不允许改写已记录、已展示的工具参数。
2. `ShellExecutor.resolve()` 的公开职责是补默认值和限制上限，不是转换命令。
3. 现有 standalone Typert projection 依赖假 workspace、协议声明镜像和非文档化 generator 假设。
4. 继续维护上述路径会增加 DSH 升级风险，并偏离“官方 API 优先、稳定为主”的要求。
5. RTK 官方支持直接调用 `rtk git status`、`rtk cargo test` 等形式，适合作为首版稳定入口。

第五版删除复杂 workaround，优先使用 DSH、Cordis、RTK、GitHub 和 Node 的公开 API。官方能力无法证明时停止，不以反射、私有 API、源码镜像或 monkeypatch 补洞。

## 2. 首版目标

开发一个长期安装到 DSH Profile 的 Cordis Host/Client 插件，安全管理官方 RTK 二进制，通过 DSH 原有 Bash/Pwsh 工具直接调用 RTK，并在 Web GUI 展示统计和 Release 管理界面。

首版可观察结果：

1. 最低兼容 DSH `0.1.0-rc.7`，并验证已发布的 `0.1.1-rc.1`。
2. 阶段 1 先证明官方 Host、Client、Remote、Client loader 和 `shell.overlay` 最小闭环；失败则暂停整个项目，不发布 Host-only 版本。
3. Windows、macOS 和 Linux 使用官方 Release 的当前平台预编译资产。
4. 下载必须有可信 SHA-256：优先核对 GitHub asset digest，存在 `checksums.txt` 时交叉验证。
5. 通过 DSH `shellEnv` 只贡献插件拥有的 `DSH_RTK_*` 变量，不修改 PATH、shell profile 或全局 RTK。
6. Agent 通过 DSH 原 Bash/Pwsh 工具执行插件 wrapper；最终命令在判权前完整可见，不做隐式替换。
7. wrapper 只设置版本 binary、`RTK_DB_PATH` 和 `RTK_TELEMETRY_DISABLED=1`，再调用官方 RTK CLI。
8. startup、clear、compact 和必要的 resume 生命周期注入短指导。
9. 首次安装基线为官方 RTK `v0.45.0`。
10. Release 目录展示官方仓库全部 `draft:false` Release，包括 stable、prerelease 和历史版本。
11. 所有公开 Release 都可查看、选择并可尝试候选下载；只有具备本平台官方资产、可信校验值且兼容性测试通过的候选才能激活。
12. 插件保证 RTK `v0.44.2` 及以后版本兼容；更旧版本只做尽力兼容并明确标注“不受保证”。
13. Token 数据跨实际安装且数据可读的 Release 聚合；每段由对应 RTK binary 读取自己的版本化 `RTK_DB_PATH`。
14. Web GUI 提供悬浮球、“总览、今日、当前仓库”三个标签页和全 Release 选择器。
15. 每个阶段独立验证、中文提交、推送并核对本地与 `origin/main` SHA。
16. 全部测试和 GitHub Release 完成后，只清理本任务可证明拥有的安装、数据、进程和派生产物，并保持插件未安装。

## 3. 明确不实现

1. 不替换或继承 DSH 内置 Bash/Pwsh executor。
2. 不在 `tools/pre-execute`、`tools/execute` 或 `ShellExecutor.resolve()` 中改写工具参数。
3. 不自动调用 `rtk rewrite` 接管每条 shell 命令。
4. 不实现“未命中语句”采集和第四个标签页。
5. 不自制 Typert generator wrapper、假 workspace、协议源码镜像或手写 generated codec。
6. 不修改、patch、vendor 或运行时 monkeypatch DSH/RTK 源码。
7. 不依赖 DSH 或 RTK 未导出的内部路径、反射结果和私有对象结构。
8. 不执行 `rtk init`，不安装全局 Hook，不修改用户 PATH、shell rc、PowerShell Profile 或全局配置。
9. 不直接读写或迁移 RTK SQLite。
10. 不把 GitHub 上可浏览但从未安装的 Release 计入 Token 统计。
11. 不保证 RTK `v0.44.2` 之前版本可用，也不为其增加专用兼容分支。
12. 不在官方 Client/Remote 闭环失败时降级发布 Host-only 残缺版本。

## 5. 兼容性口径

### 5.1 DSH

1. 最低支持 `0.1.0-rc.7`。
2. `0.1.1-rc.1` 是 npm 已发布的最高版本，当前 dist-tag 为 `next`；必须进入兼容矩阵。
3. 阶段 1 在 rc.7 和 rc.1 分别验证官方 Client/Remote 最小闭环。
4. 任一版本差异必须通过公开 API 处理；禁止维护按内部结构探测的兼容层。
5. rc.7 无法完成官方闭环时，项目停止并报告，不抬高最低版本掩盖失败。

### 5.2 RTK

1. GitHub tag 仍作为不透明目录 identity；目录排序使用 `published_at` 和 release id。
2. 兼容保证以候选 binary 报告的语义版本为准：`>=0.44.2` 属于保证范围。
3. 无法报告标准语义版本或 `<0.44.2` 的候选属于尽力兼容范围。
4. 两类候选都必须经过相同资产、checksum/digest、安全解压和运行测试；没有绕过开关。
5. 保证范围测试失败属于插件缺陷并阻断阶段；尽力兼容版本失败只阻止该候选激活，不扩大专用适配。
6. 所有 `draft:false` Release 始终可见、可选和可查看失败原因。

## 6. 已确认官方事实

1. DSH 插件包通过 `dsh.bundle` 指向 patch，并通过 `dsh plugin --profile <name> add <package>` 安装。
2. DSH `shellEnv` 允许插件注册 fiber-owned `DSH_*` 环境变量。
3. DSH 工具参数在 pre-policy 阶段已经记录和展示，官方契约排除输入改写。
4. `tools/execute` around-dispatch 可以做 timeout、retry 或 metrics，但 call identity 不可变。
5. RTK 官方文档支持直接以 `rtk <tool> <args>` 形式执行命令。
6. RTK `gain --all --format json` 是机器可读统计来源。
7. `RTK_TELEMETRY_DISABLED=1` 是官方禁用遥测方式。
8. RTK `v0.45.0` 为公开 stable，并提供目标平台资产、`checksums.txt` 和 GitHub SHA-256 digest。

## 8. 已批准决策

1. 首版由 Agent 直接调用 RTK wrapper，不透明接管 shell。
2. 首版 UI 为“总览、今日、当前仓库”三个标签页。
3. 所有公开 Release 可见、可选、可尝试下载安装；保证 `v0.44.2` 及以后，之前版本尽力兼容。
4. 统计跨实际安装且数据可读的历史 Release 聚合。
5. 最低兼容 DSH rc.7，同时验证 rc.1；官方 Client/Remote/Slot 闭环失败则暂停整个项目。
6. 不发布 Host-only 残缺版本，不制作复杂 Typert workaround。
7. 现有未提交阶段 1 实验代码不作为基线，实施开始后按退休清单精确删除并从阶段 0 HEAD 重做。
