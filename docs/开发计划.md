## 1. 目标

开发一个长期安装到 DeepSeek Harness Profile 的 Cordis 插件，通过官方 RTK 压缩模型可见的 shell 命令输出，并在 Web GUI 右下角提供可拖动的统计悬浮球。

首版必须实现以下可观察结果：

1. Linux 与 macOS 的 Bash executor、Windows 的 PowerShell executor 都能接入 RTK。
2. 每条非空 shell 命令都交给当前活动 RTK 二进制的 `rtk rewrite` 判定，不在插件中复制或裁剪 RTK 规则。
3. 新建、清空、恢复会话以及每次压缩后，向 Agent 注入“语义等价时尽量使用 RTK 支持的单条命令”的短指导。
4. 首次安装使用已验证基线 RTK `v0.45.0`，根据平台选择官方预编译资产并验证 SHA-256。
5. 在线目录展示 RTK GitHub `releases` 中所有公开发布版本，包括 stable、prerelease 和历史版本，不强制稳定版通道。
6. 用户可浏览并打开任一公开 Release；stable/prerelease/历史版本不受通道限制。具备当前平台官方资产和可验证 checksum/digest 的 Release 可进入候选事务，并须通过完整 RTK 兼容性测试才能激活。
7. 更新检查、下载、校验、测试或激活失败时继续使用旧活动版本；首次安装失败时透明退化为 DSH 原有命令语义。
8. 默认悬浮球显示“已节省 / 总接管”估算 Token，可拖动，点击后展开详细数据。
9. 详细面板包含“总览、今日、当前仓库、未命中语句”四个标签页；总览同时提供 Release 选择、更新进度和测试报告。
10. Token 数据来自各版本 RTK 的 `gain` JSON；未命中数据来自执行时活动 RTK 的 `rewrite` 结果。
11. 项目采用标准 TypeScript 工程结构，所有手工维护文件不超过 400 个物理行，并以自动化门禁保证高内聚、低耦合和无循环依赖。
12. 所有维护型源码使用中文文件级、函数级和关键语句级三层注释。
13. 每个实施阶段都由 GitHub 账号 `SeireiA` 验证、提交并推送；远端 SHA 与本地一致后才能进入下一阶段。
14. 代码、测试和 GitHub Release 完成后，清理全部任务创建的测试安装、数据、进程和派生产物，保持未安装状态交给用户手动完成初版安装。

## 3. 已确认事实

1. DSH `agent/session-start` 支持 `startup`、`resume`、`clear`、`compact`，并允许 `agent.inject()` 注入模型可见上下文。
2. DSH Linux/macOS 默认使用 Bash executor，Windows 默认使用 PowerShell executor。
3. DSH `ShellExecutor.resolve()` 与后台 `start()` 是同步边界。
4. RTK `rewrite` 是改写规则的唯一真相源，支持其版本内定义的简单、复合、多行、环境前缀和安全管道语法。
5. RTK `gain --all --format json` 提供累计、每日、每周、每月数据，`--project` 按 cwd 及子目录过滤。
6. RTK `rtk test <cmd>` 是通用测试输出压缩器，不是完整二进制自检。
7. 2026-08-21 的 GitHub API 快照返回 281 个公开 Release，其中 201 个是 prerelease；少数早期 Release 缺少特定平台资产或 checksum，因此目录必须分页并显示平台兼容状态。
8. DSH `dsh plugin --profile <name> <pnpm args>` 会把 `add/remove/list` 等参数转交给 Profile 目录中的 pnpm，可用于测试安装和卸载。
9. RTK Token 数是基于输出字节的估算，不是模型供应商账单 Token。

## 4. 明确口径

1. “全部 Release”指 GitHub 官方仓库中 `draft: false` 的公开 Release；stable、prerelease 和历史版本都进入目录。
2. Release tag 按不透明标识处理，不要求 tag 必须是标准 semver；排序以 GitHub `published_at` 和 release id 为依据。
3. “全部 Release 可选择”指每个公开 Release 行都能被选中并打开详情；只有通过资产和 checksum/digest 预检的行才启用“安装并切换”，测试通过后才可激活。不可用行必须显示原因，不能被稳定版通道过滤或从目录隐藏。
4. 选择比当前版本更早的 Release 属于显式版本切换；选择 prerelease 属于显式预发布版本切换。两者允许，但必须二次确认并经过相同测试门禁。
5. “总接管”和“已节省”分别是所有可读版本数据段的 `total_input` 与 `total_saved` 之和。
6. “当前仓库”由前台会话 cwd 向上查找最近 `.git` 根；没有 `.git` 时退回 cwd，并跨同仓库会话、跨 RTK 版本聚合。
7. “未命中”以完整 shell 工具调用为审计单位；技术超时或 runtime 故障单独统计，不混入 RTK 未命中率。
8. 总览比较最近 7 天与此前 7 天；今日比较今日与昨日；当前仓库比较仓库占全局比例及仓库今日与昨日。
9. “清理测试环境”只删除本任务证明为测试创建的派生状态，不删除用户原有 DSH Session、其他插件、全局 RTK、项目 Git 历史或远端 Release。

## 5. 非目标

1. 不修改 DeepSeek Harness 核心仓库或内置插件。
2. 不执行 `rtk init`，不安装全局 Hook，不修改用户 PATH、shell rc 或 PowerShell Profile。
3. 不直接解析、查询或迁移 RTK SQLite。
4. 不宣称统计数等于供应商账单 Token 或整个会话 Token。
5. 首版不接管 DSH 的 `read`、`grep`、`glob` 等非 shell 工具。
6. 首版不实现跨设备同步、云端遥测、账号或远程统计存储。
7. 首版不做会话级 Token 归因。
8. 不从源码构建缺失平台资产的历史 RTK Release，也不跳过 checksum 或测试门禁。
9. 不静默安装或切换任何 Release。
10. 首版不提供自动删除历史版本数据的产品 UI。
11. 拖动位置首版不跨页面刷新持久化。
12. 不保留第二套 rewrite 白名单、第二套 Token 真相或第二个活动版本 Owner。

## 7. 再次审批点

审批第四版计划将同时确认：

1. 仓库为公开、非 fork 的 `SeireiA/dsh-plugin-rtk`，默认分支 `main`，Topic 包含 `dsh-plugin`。
2. `v0.45.0` 只作为首次安装基线，不作为在线更新通道限制。
3. GitHub 所有公开 Release 都进入分页目录，包括 stable、prerelease 和历史版本。
4. 用户可选中任一公开 Release 查看详情，并可对通过平台资产/校验预检的 prerelease 或历史版本发起候选事务；draft、缺少本平台资产、缺少可信校验值或测试失败的候选不可激活。
5. 所有候选都执行 version、rewrite、真实 `rtk test`、read/grep/ls、global/project gain 测试，不提供绕过门禁开关。
6. 更新采用 side-by-side 安装、版本化 `RTK_DB_PATH`、原子活动描述符和失败回滚。
7. 每条命令委托活动版本 `rtk rewrite`，500ms 有界同步分类只解析字符串，DSH approval 始终是唯一权限权威。
8. 新建、清空和压缩后注入固定指导，resume 仅在缺失同版本来源时补入。
9. 详细面板保留四个标签页，总览增加全 Release 选择、更新进度和测试报告。
10. 当前仓库跨会话、跨版本聚合，不声明会话级 Token。
11. 未命中命令先脱敏，带 RTK 版本聚合并限制为最近 1000 个不同项。
12. 所有手工维护文件硬限制 400 个物理行，目标值 250 行；生成文件与 lockfile 仅能通过显式机器生成例外排除。
13. 生产函数不超过 60 行、圈复杂度不超过 10、嵌套不超过 4 层、参数不超过 5 个；依赖图必须无环。
14. 所有手工维护源码采用三层中文注释，生成文件不手工修改。
15. 每个实施阶段由 `SeireiA` 提交并推送，远端 SHA 一致后才继续，禁止 force push。
16. 完成代码、测试和 GitHub Release 后，只在基线、package resolution、acceptance ownership marker 和测试结束清单四重 guard 通过时卸载测试插件并删除测试状态；任何可能的用户状态都保留并停止清理。
17. 清场完成后不重新安装插件，只提供发布包、checksum 和手动初版安装步骤给用户。
18. 项目使用 MIT License。

实施必须继续遵守逐阶段验证、提交、推送和 SHA 对账门禁；阶段 9 完成清场前不得宣告整体完成。
