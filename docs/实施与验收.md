## 5. 阶段 1：退休实验路径与官方双端闭环

### 5.1 TaskStartSnapshot 与退休

1. 记录 branch、HEAD、origin、工作树和全部未提交实验文件。
2. 把实验路径分类为任务内部 `code-retirement`，列出保留/删除清单。
3. 保留阶段 0 文件和已批准第五版文档。
4. 精确删除假 workspace/projection、协议镜像、executor replacement 及专用测试/config。
5. 扫描旧 generator、executor 和镜像术语的 lingering references。
6. 不删除 DSH checkout、Profile、全局 RTK、用户数据、Git 历史或远端对象。

### 5.2 rc.7/rc.1 官方闭环 stop gate

分别在隔离 DSH `0.1.0-rc.7` 和 `0.1.1-rc.1` 环境证明：

1. 外部 package 通过官方工具构建 Host 和 Client entry。
2. 官方 Typert 流程生成 Host artifact、Remote contribution 和 codec。
3. package exports、`dsh.client`、`./typert` 和 `./remote` 被官方 loader 发现。
4. 最小 `probe(): { ok: true }` 从 Client 成功调用 Host。
5. Client 在 `shell.overlay` 注册并卸载最小 entry。
6. install/start/stop/reload/remove 和 disposer 全部生效。

禁止源码复制、协议镜像、假 workspace、手写 codec 和 runtime patch。任一版本失败即记录 `blocked-official-api`，暂停整个项目；不进入后续阶段、不发布 Host-only 版本。

### 5.3 最小双端骨架

stop gate 通过后实现：

1. 一个 Host entry 和一个返回 `not-installed` 的 `RtkService`。
2. shellEnv contribution；无活动 Runtime 时不返回变量。
3. lifecycle listener；无活动 Runtime 时不注入。
4. 最小 typed Remote、Client entry 和 overlay probe。
5. `dsh.bundle` patch 只插入本插件，不禁用/替换 shell executor。
6. 双版本启动、卸载、重载、codec 和 disposer 测试。

完成全量门禁、双审查、提交、推送、SHA 和 CI 后才能进入阶段 2。

## 6. 阶段 2：基线 Runtime 与直接 wrapper

1. 定义 Release identity、platform asset、installed segment 和 active pointer schema。
2. 通过 GitHub 官方 API 读取 `v0.45.0` 元数据。
3. 选择当前平台官方资产，交叉校验 asset digest 和 `checksums.txt`。
4. 流式下载到 owner-marked 临时目录，限制大小和 redirect host。
5. 安全解压到 side-by-side Release 目录。
6. 生成 wrapper；只设置版本 DB、禁用遥测并 exec 官方 binary。
7. 使用 `--version`、直接 RTK fixture command 和 gain JSON 做兼容性测试。
8. 原子写入 active pointer。
9. shellEnv 暴露 `DSH_RTK_WRAPPER` 和 `DSH_RTK_VERSION`。
10. 验证原 executor、approval、sandbox、workdir、timeout 和 background 未改变。
11. 首次安装失败时保持 `not-installed`，原 shell 完全可用。

## 7. 阶段 3：全 Release 目录与安全切换

1. 分页读取 GitHub 所有 `draft:false` Release，保留 stable、prerelease 和历史版本。
2. 所有行可选择和查看详情，不以稳定通道或 `v0.44.2` 门槛隐藏。
3. 使用明确平台 alias 选择资产并显示缺资产/校验原因。
4. 交叉验证 GitHub digest 与 `checksums.txt`。
5. 下载后通过 binary reported version 判定 `guaranteed` 或 `best-effort`。
6. `>=0.44.2` 属于保证范围；更旧或不可解析版本明确标注“不受保证”。
7. 两类候选执行同一 side-by-side 下载、解压、wrapper 和完整测试。
8. guaranteed 候选失败阻断阶段并按插件缺陷修复；best-effort 失败只阻止该候选，不增加专用适配。
9. 同时只允许一个更新事务；成功后原子切换，失败继续旧 Runtime。
10. 中断后只清理带本事务 marker 的候选临时目录。
11. 350 条 fixture 覆盖分页、支持等级、prerelease、历史版本、缺资产、缺校验、漂移和回滚。
12. 在线只读验收把全部公开 release id 与 Host catalog 双向集合对账。

## 8. 阶段 4：Session 指导

1. 有活动 Runtime 时注册 startup、clear、compact 和 resume 指导。
2. typed source 使用 `kind:rtk-guidance`、`version:2` 和活动 tag。
3. 指导只建议 Bash/Pwsh 直接调用 `$DSH_RTK_WRAPPER`。
4. 不告诉模型修改 PATH、执行 `rtk init` 或绕过 DSH 权限。
5. 无 Runtime 时不注入。
6. 验证每生命周期一次、compact 后恢复、resume 去重和卸载清理。

## 9. 阶段 5：跨已安装 Release 统计

1. 定义单 segment gain schema、source metadata、partial 和 aggregate contract。
2. 对每个已安装 segment 使用对应 wrapper/DB 调用 global gain。
3. 使用 Host 验证后的 repository cwd 调用各 segment project gain。
4. 对 total 求和、比例重算、daily/weekly/monthly 周期键合并。
5. 计算 overview、today、repository 三种 snapshot。
6. 单 segment 使用 5 秒缓存并去重并发；installed/data revision 变化使聚合缓存失效。
7. 不可读 segment 进入 `unreadableReleases`，其他段继续返回并标记 partial。
8. 不读取 SQLite，不实现未命中诊断。

## 10. 阶段 6：完整 Remote 与状态投影

1. 复用阶段 1 已验证的官方 Typert 链路，不重新发明 generator。
2. 实现 `snapshot`、`releases` 和 `applyRelease` typed contract。
3. Remote 只校验输入并调用 RtkService。
4. Client 使用 5 秒/15 秒轮询，不增加 observable。
5. 投影 source/unreadable Releases、支持等级、事务进度和稳定错误 code。
6. 验证 rc.7/rc.1 codec、并发、取消、卸载和 JSON 边界。

## 11. 阶段 7：三标签 UI

1. 注册 `shell.overlay` 悬浮球。
2. 实现总览、今日、当前仓库三标签页。
3. 实现全 Release 搜索、支持等级筛选、分页、详情和候选操作。
4. 显示跨版本聚合、partial/stale 和当前活动 tag。
5. 实现拖动、键盘、暗色、reduced motion 和完整状态。

## 13. 阶段 9：清理与交接

### 13.2 清理顺序

1. 停止任务启动的 watcher/server/RTK/测试 DSH 进程。
2. 从隔离 Profile 移除测试插件。
3. 删除任务拥有的 Runtime、DB、归档、截图、coverage 和 tarball。

5. 验证当前 GUI Profile、用户 Session、其他插件、全局 RTK、Git 和远端 Release 未改变。
