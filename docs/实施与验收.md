## 5. 阶段 1：历史退休、Host gate 与 Client gate

### 5.1 已完成退休

第五版 TaskStartSnapshot、12 个 tracked delta 恢复、15 个 untracked 实验删除和清场证据保持历史有效。不得恢复假 workspace、协议镜像、executor replacement、参数 mutation 或专用 fallback。

### 5.2 Stage 1H：rc.7/rc.1 Host enforcement stop gate

分别在隔离 DSH `0.1.0-rc.7` 和 `0.1.1-rc.1` 环境证明：

1. Standalone package 只用公开 Host build、`dsh.bundle` patch 和安装命令完成 install/start/stop/reload/remove。
2. 目标版本完整内置 shell 表必须精确为 `bash`/`pwsh`，两者都要求 `exec.arguments.command:string`；空字符串也进入 classification，missing/wrong-type 严格拒绝，其他 Tool 明确不在保证范围。
3. Stage 1H 首次实现 production `RtkCommandGate`，但只接 test-owned fake rewrite executable 与 ephemeral lease；Stage 2 才创建真实 segment、wrapper 和 active pointer。
4. Async classifier 使用 `{ prepend:true }` 和 DSH registry-issued `exec.token`，写 one-shot start/allow receipt 后调用 `next()`；`next()` 只恢复 pre-execute chain，同步 terminal `ctx.tools.guard()` 原子消费，missing/mismatch/expired 一律拒绝。
5. Fake executable 覆盖 exit `0` rewrite/converged、`1` no-match、`2` policy deny、`3` ask rewrite/final ask，以及 stdout/stderr、encoding/newline 的穷尽矩阵；未列组合严格拒绝。
6. 真实 rc.7/rc.1 证明 scheduler 顺序为 waterfall → 必要时 approval → guard → execute；前后注册的 listener/guard 覆盖 `next()`、throw、ask、deny 和 short-circuit。Classifier deny 不触发 approval；missing receipt 即使在 ask 后也不得进入 `tools/execute`/executor/process 或产生副作用。
7. Agent retry 是新 ToolExecution；gate 不自动执行/回显 suggestion，也不保证任意 shell program 都可构造成功。Raw applicable、wrapper-shaped retry、manual-retry-required、再次 rewrite、重复 deny 与 Bash/Pwsh 模板都纳入测试。
8. Receipt 状态机覆盖 downstream throw、approval cancel、guard throw、abandoned result、atomic consume、10 分钟 expiry、result/disposer 幂等清理和 symbol 不复用；任何 stale receipt 都不能授权。
9. Abort/dispose/generation 切换时取消 child、1 秒内 reap 并忽略迟到输出；secret fixture 证明 denial/result/log projection 不回显 command、stdout/stderr、路径、环境或 suggestion。
10. Stop/reload/remove 以 exclusive latch 进入 draining，禁止新 receipt，保留 pointer/tombstone 与 guard 至 pipeline quiescent 后再 inactive；覆盖 classifier allow→downstream pending→stop/switch/reload→guard race。无法证明 quiescence 即 1H blocker。
11. 无 lease 起始调用写 inactive-start receipt；只在 active 尚未 commit 的 guard decision 放行。Activation commit 前已过 guard 的调用不追溯拦截，尚未过 guard 的调用因 mode mismatch 拒绝。

禁止注册第二个 shell Tool、修改参数、around-dispatch 改写、shell resolve 改写、全局 Hook、PATH/profile patch 或私有 API。无法穷举 identity/schema、证明 pre-execute→必要时 approval→guard→execute 顺序或任一目标版本失败，都记录 Stage 1H blocker 并停止阶段 2 至阶段 5。

## 8. 阶段 4：强制判定加固与 Session 指导

Production gate 已由 Stage 1H 拥有、Stage 2 接入真实 Runtime；本阶段不创建第二个 classifier 或 applicability Owner，只做跨平台加固和采用率优化：

1. 固化 bounded denial reason：稳定 code、tool/platform、retry kind 与通用 Bash/Pwsh wrapper 模板，总长不超过 1 KiB；不含原 command、raw output、suggestion、绝对路径、环境或 stack。
2. 验证 raw applicable→deny→Agent wrapper-shaped retry→RTK no-match/exit-0-same→DSH policy/executor、exit-3-same→DSH ask、inactive→execute、contract failure→deny。
3. 验证 wrapper path 空格/非 ASCII、literal `rtk` 不在 PATH、compound/pipeline/redirect/heredoc/env/substitution 与 PowerShell 对应语法；插件从不机械前缀化或解析 shell。
4. 验证 suggestion 改变参数也不会自动执行、不继承原 approval；重复 rewrite 继续 deny，不设 prefix bypass、不自动重试。
5. 注册 startup、clear、compact 和必要 resume 指导，typed source 使用 `kind:rtk-guidance`、`version:3` 和 active release identity。
6. Guidance 给出 Bash/Pwsh 精确 wrapper 语法，要求能保持语义时优先直接调用 wrapper；compound 无法安全构造时停止，不重复副作用或绕过权限。
7. 不告诉模型修改 PATH、执行 `rtk init`，不保存 command、rewrite suggestion、denial 原文或 per-call blocked 状态。
8. 验证 guidance 每生命周期一次、compact 后恢复、resume 去重、Release 切换更新和卸载清理。
9. 受控 Agent 场景统计首次 wrapper 使用和 deny 后成功重试，仅作测试证据，不建立生产“未命中”数据 Owner。
10. 对 RTK permission/bypass 历史风险做回归：rewrite 仅提供 classification，不授予 DSH allow/approval，最终调用始终重新判权。
